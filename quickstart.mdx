This page takes you from an API key to a message that you sent and tracked. You need an iSnap account ([sign up](https://platform.isnap.ai/signup)) and one line whose status is `active`. A new account has no line, and `GET /v1/lines/my` returns an empty `lines`: see [Getting a line](/guides/getting-a-line).

<Warning>
  iSnap has no test environment. Every send on this page is a real message to a real recipient, from a real line of your account. An `isnap_test_` account key sends too: see [Test keys](/authentication#test-keys). Send to a phone number of your own.
</Warning>

## Create an API key

Create an API key in the [iSnap dashboard](https://platform.isnap.ai). The dashboard shows the full key once: store it in a secret manager. The samples of every page read it from the environment variable `ISNAP_API_KEY`.

```bash
# Paste the key at the prompt: it is not shown and not written to your shell history.
read -rs ISNAP_API_KEY && export ISNAP_API_KEY
```

Set the variable yourself. Never paste a key into a prompt for an AI agent: start the agent in an environment that already holds the variable.

The key is `isnap_live_` or `isnap_test_` followed by 64 hexadecimal characters. [Authentication](/authentication) describes the keys and every refusal.

## Make a first call

`GET /v1/version` needs no key. It tells you that you reach the API.

```bash
curl -sS https://api.isnap.ai/v1/version
```

The response contains the version of the API, for example:

```json
{
  "success": true,
  "data": { "version": "2.39.0" },
  "trace_id": "0af7651916cd43dd8448eb211c80319c",
  "request_id": "req_4Tn7Bw9Rz3Lc6Yp1Hd8Xk2mQv"
}
```

The result of a call is in `data`: see [Conventions](/api-reference/introduction#conventions). Keep `trace_id` and `request_id` when you report a problem.

Then list your lines with your key. The TypeScript samples use the SDK (`npm install @isnap/sdk`), which needs Node.js 20 or later and is ESM only: see the [SDK overview](/sdk/overview). The Python samples use `requests` (`pip install requests`).

<CodeGroup>

```bash curl
curl -sS https://api.isnap.ai/v1/lines/my \
  -H "Authorization: Bearer $ISNAP_API_KEY"
```

```typescript TypeScript
import { ISnapClient } from '@isnap/sdk'

const client = new ISnapClient({ apiKey: process.env.ISNAP_API_KEY ?? '', maxRetries: 2 })

const { lines } = await client.lines.listMine()
for (const line of lines) {
  console.log(line.id, line.billing_tier, line.status, line.inbound_only)
}
```

```python Python
import os

import requests

response = requests.get(
    "https://api.isnap.ai/v1/lines/my",
    headers={"Authorization": f"Bearer {os.environ['ISNAP_API_KEY']}"},
    timeout=30,
)
body = response.json()
if response.status_code != 200:
    raise SystemExit(f"{body['error']['status']} {body['error']['code']}: {body['error']['message']}")
for line in body["data"]["lines"]:
    print(line["id"], line["billing_tier"], line["status"], line["inbound_only"])
```

</CodeGroup>

`GET /v1/lines/my` returns your lines whose status is `active` or `reserved`. Note the `id` of a line whose `status` is `active`: only an active line sends. If `inbound_only` is `true`, the line can message a contact only after that contact wrote to it: see [Line kinds](/concepts#line-kinds).

## Send a message

`POST /v1/messages` sends one message to one phone number from one line. Replace the line id with yours, and `to` with a phone number of your own.

<CodeGroup>

```bash curl
IDEMPOTENCY_KEY=$(uuidgen) # Store it with your record of the message: reuse it to retry.

curl -sS https://api.isnap.ai/v1/messages \
  -H "Authorization: Bearer $ISNAP_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  -d '{
    "line_id": "line_8Xk2mQ4vTn7Bw9Rz3Lc6Yp1Hd",
    "to": "+14155550123",
    "body": "Hello from iSnap"
  }'
```

```typescript TypeScript
import { randomUUID } from 'node:crypto'
import { APIError, ISnapClient } from '@isnap/sdk'

const client = new ISnapClient({ apiKey: process.env.ISNAP_API_KEY ?? '', maxRetries: 2 })

const idempotencyKey = randomUUID() // Store it with your record of the message: reuse it to retry.

try {
  const message = await client.messages.send(
    {
      line_id: 'line_8Xk2mQ4vTn7Bw9Rz3Lc6Yp1Hd',
      to: '+14155550123',
      body: 'Hello from iSnap'
    },
    { idempotencyKey }
  )
  console.log(message.id, message.status, message.scheduled_for, message.schedule_reason)
} catch (err) {
  if (!(err instanceof APIError)) throw err
  console.error(err.status, err.code, err.message, `trace_id=${err.traceId}`, `request_id=${err.requestId}`)
  process.exitCode = 1
}
```

```python Python
import os
import time
import uuid

import requests

idempotency_key = str(uuid.uuid4())  # Store it with your record of the message: reuse it to retry.

for attempt in range(3):
    try:
        response = requests.post(
            "https://api.isnap.ai/v1/messages",
            headers={
                "Authorization": f"Bearer {os.environ['ISNAP_API_KEY']}",
                "Idempotency-Key": idempotency_key,
            },
            json={
                "line_id": "line_8Xk2mQ4vTn7Bw9Rz3Lc6Yp1Hd",
                "to": "+14155550123",
                "body": "Hello from iSnap",
            },
            timeout=30,
        )
        break
    except (requests.ConnectionError, requests.Timeout):
        # No response: iSnap may have accepted the message. Retry with the same key, up to 2 times.
        if attempt == 2:
            raise
        time.sleep(2**attempt)
body = response.json()
if response.status_code != 202:
    error = body["error"]
    raise SystemExit(
        f"{error['status']} {error['code']}: {error['message']} "
        f"(trace_id={body['trace_id']}, request_id={body['request_id']})"
    )
message = body["data"]
print(message["id"], message["status"], message["scheduled_for"], message["schedule_reason"])
```

</CodeGroup>

The API returns `202` with the message. A `202` means that iSnap accepted the message, never that it was sent. These are the fields to read first, out of the whole message object:

```json
{
  "success": true,
  "data": {
    "id": "msg_3Lc6Yp1Hd8Xk2mQ4vTn7Bw9Rz",
    "line_id": "line_8Xk2mQ4vTn7Bw9Rz3Lc6Yp1Hd",
    "direction": "outbound",
    "to": "+14155550123",
    "from": "+14155550124",
    "body": "Hello from iSnap",
    "status": "queued",
    "service": null,
    "queued_at": "2026-10-08T14:22:57.392Z",
    "scheduled_for": "2026-10-08T14:22:57.392Z",
    "schedule_reason": null
  },
  "trace_id": "0af7651916cd43dd8448eb211c80319c",
  "request_id": "req_4Tn7Bw9Rz3Lc6Yp1Hd8Xk2mQv"
}
```

Send `Content-Type: application/json` with every body. The `Idempotency-Key` header makes a retry safe: a second request with the same key and the same body sends nothing and, while the line is `active`, returns the same message, for as long as iSnap keeps that message, at least 72 hours. Generate one key per message, and reuse it only to retry that message. See [Idempotency](/idempotency#operations-that-honor-the-key).

The responses to a first send:

| Response | Meaning | What to do |
| --- | --- | --- |
| `202` with `status: queued` | iSnap accepted the message. It waits for the line's device, which sends it when it takes it. | Track it: see the next section. |
| `202` with `status: scheduled` | iSnap holds the message until `scheduled_for`. `schedule_reason` says why. With `quiet_hours`, the message was accepted outside the hours in which the line sends, by default 08:00 to 20:59 in the recipient's local time. | Nothing. When the time arrives, iSnap releases the message, or holds it again with a new `scheduled_for`. A message still held 48 hours after iSnap accepted it fails, even when its `scheduled_for` is later. See [Held messages](/guides/sending-limits#held-messages) and [Quiet hours](/guides/sending-limits#quiet-hours). |
| `400 bad_request` | `to` is not a valid phone number, or is an email address. | Send to a phone number. A number without a country code is read as a US number. |
| `400 line_not_active` | The line is neither `active` nor `suspended`, for example `reserved`. | Send from an active line. |
| `403 line_suspended` | The line is suspended. | See [Line statuses](/concepts#line-statuses). |
| `403 outbound_first_forbidden` | The line is inbound-only and this recipient never wrote to it. | Write to the line from the recipient's phone first, or send from a two-way line. |
| `404 not_found` | The line does not exist or is not yours. | Check `line_id` against `GET /v1/lines/my`. |
| `401 unauthorized`, `403 forbidden` | iSnap refused the credential. | See [Troubleshooting](/authentication#troubleshooting). |

[Sending messages](/guides/sending-messages) describes the whole request and every refusal.

## Read its status

Read the message by its id. `status` moves from `queued` to `sent` when the line's device reports that it sent the message, then to `delivered` and `read` when the device reports them. `service` then says what the device used: `iMessage`, `SMS` or `RCS`.

<CodeGroup>

```bash curl
curl -sS https://api.isnap.ai/v1/messages/msg_3Lc6Yp1Hd8Xk2mQ4vTn7Bw9Rz \
  -H "Authorization: Bearer $ISNAP_API_KEY"
```

```typescript TypeScript
import { ISnapClient } from '@isnap/sdk'

const client = new ISnapClient({ apiKey: process.env.ISNAP_API_KEY ?? '', maxRetries: 2 })

const message = await client.messages.get('msg_3Lc6Yp1Hd8Xk2mQ4vTn7Bw9Rz')
console.log(message.status, message.service, message.sent_at, message.delivered_at, message.error_code)
```

```python Python
import os

import requests

response = requests.get(
    "https://api.isnap.ai/v1/messages/msg_3Lc6Yp1Hd8Xk2mQ4vTn7Bw9Rz",
    headers={"Authorization": f"Bearer {os.environ['ISNAP_API_KEY']}"},
    timeout=30,
)
body = response.json()
if response.status_code != 200:
    raise SystemExit(f"{body['error']['status']} {body['error']['code']}: {body['error']['message']}")
message = body["data"]
print(message["status"], message["service"], message["sent_at"], message["delivered_at"], message["error_code"])
```

</CodeGroup>

Three rules to know before you build on `status`:

- iSnap learns "delivered" and "read" only from the line's device. With no report, a message stays `sent`.
- A message stays `queued` while it waits for the line's device.
- iSnap deletes a message at least 72 hours after it recorded it. Once deleted, `GET /v1/messages/{id}` returns `404 not_found`.

[Message statuses](/concepts#message-statuses) lists every status, what sets it, and which ones are final.

A message carries personal data: the handles in `to` and `from`, and the text in `body`. Request it only when needed. Do not copy it into logs, tickets or other tools. Refer to a contact by an id of your own.

## Receive its events

Reading a message repeatedly uses your request-rate limit. Let iSnap call you: create a webhook subscription with the URL of your endpoint and the event types you want.

The response contains the signing secret: run the command where its output is not logged, and store the secret in your secret manager.

<CodeGroup>

```bash curl
curl -sS https://api.isnap.ai/v1/webhooks \
  -H "Authorization: Bearer $ISNAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://hooks.your-domain.example/isnap",
    "events": ["message.*"]
  }'
```

```typescript TypeScript
import { ISnapClient } from '@isnap/sdk'

const client = new ISnapClient({ apiKey: process.env.ISNAP_API_KEY ?? '', maxRetries: 2 })

// maxRetries: 0, because this operation does not honor Idempotency-Key:
// a retry after a lost response would create a second subscription.
const subscription = await client.webhooks.create(
  { url: 'https://hooks.your-domain.example/isnap', events: ['message.*'] },
  { maxRetries: 0 }
)
console.log(subscription.id)
// Store subscription.secret now as ISNAP_WEBHOOK_SECRET: no other call returns it.
```

```python Python
import os

import requests

response = requests.post(
    "https://api.isnap.ai/v1/webhooks",
    headers={"Authorization": f"Bearer {os.environ['ISNAP_API_KEY']}"},
    json={"url": "https://hooks.your-domain.example/isnap", "events": ["message.*"]},
    timeout=30,
)
body = response.json()
if response.status_code != 201:
    raise SystemExit(f"{body['error']['status']} {body['error']['code']}: {body['error']['message']}")
subscription = body["data"]
print(subscription["id"])
# Store subscription["secret"] now as ISNAP_WEBHOOK_SECRET: no other call returns it.
```

</CodeGroup>

The response contains the signing secret of the subscription, once. Do not send this request twice: `POST /v1/webhooks` does not honor `Idempotency-Key`, and a second request creates a second subscription that receives every event too. If the response does not arrive, list your subscriptions with [`GET /v1/webhooks`](/api-reference/webhooks/list-webhooks) and look for your URL before you create one again. If the subscription exists, call [`POST /v1/webhooks/{id}/rotate-secret`](/api-reference/webhooks/rotate-webhook-secret) to get a signing secret: no other call returns the secret of the first response.

For the message you sent, iSnap sends these events to your endpoint:

| Event | When |
| --- | --- |
| `message.queued` | iSnap accepted the message without holding it, or released a held message. |
| `message.scheduled` | iSnap accepted the message and holds it. |
| `message.sent` or `message.failed` | The line's device reported that it sent the message, or the message failed. |
| `message.delivered`, `message.read` | The device reported a delivery receipt or a read receipt. |

Each event carries the whole message in `data.message`. Before you rely on events:

- Verify the signature of every delivery: see [Verifying signatures](/webhooks/verifying-signatures).
- Deduplicate on `event_id`. See [Duplicates](/webhooks/delivery#duplicates).
- Delivery order is not guaranteed. Order events by the timestamps inside `data`, not by arrival. See [Order](/webhooks/delivery#order).
- Events do not announce every change, and an event can be missed: see [What events do not announce](/webhooks/event-catalog#what-events-do-not-announce). Reconcile from `GET /v1/messages/{id}` and `GET /v1/messages`.

[Webhooks overview](/webhooks/overview) says what your endpoint must do.
