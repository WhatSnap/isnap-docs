---
title: "Send a contact card"
description: "Builds a contact card from the fields of the request and sends it to the contact of a chat as a message."
openapi: "POST /v1/chats/{chat_id}/share-contact-card"
---

- **Credential:** an API key. A trial key returns `401 unauthorized`. See [Contact cards](/guides/conversations#contact-cards).
- **Line-scoped keys:** a [line-scoped key](/authentication#line-scoped-keys) gets `403 forbidden` when the chat's line is outside its list.
- **Test keys:** a card sent with an `isnap_test_` account key reaches the real contact: see [Test keys](/authentication#test-keys).
- **`Idempotency-Key`:** read, and never replayed. Once a call has created the card's message, a repeat with the same key returns `409 idempotency_conflict`. When no message was created, the repeat sends the card, and so does every repeat without a key: send a key with every call. A key that a reaction already used on the chat's line is not refused: the call returns `202` with the id of the reaction entry in `message_id`, and sends nothing. Use a new key for every call. Do not retry this call blindly: when you did not receive the response, look for the message with `GET /v1/messages` before you resend the card. See [Messages, reactions and contact cards](/idempotency#messages-reactions-and-contact-cards) for the scope and the lifetime of the key.
- **Events:** the events of a send, from `message.queued` or `message.scheduled` on.
- **Personal data:** the card holds a person's name, phone numbers, email addresses, organization, note and photo, and its file name holds the name. Request it only when needed, do not copy it into logs, tickets or other tools, and refer to a contact by an id of your own.
- **A message:** the card is a message with one attachment. The sending limits, the holds, the events and the errors of `POST /v1/messages` apply. One difference: on an iMessage line the card always asks for the typing indicator, whatever the line's `default_use_typing_indicator`. `ignore_quiet_hours` works as on `POST /v1/messages`: see [Sending during quiet hours](/guides/sending-limits#sending-during-quiet-hours). See [Sending messages](/guides/sending-messages).
- **Response:** `status` always reads `queued`, even when iSnap holds the message: read the message with `GET /v1/messages/{id}`. The response carries no `X-iSnap-Quota-` header.

## Errors

| Status | `error.code` | When |
| --- | --- | --- |
| 400 | `validation_failed` | `first_name` is missing, a phone number is not in E.164, an email address is invalid, `avatar_url` is not an HTTPS URL, or none of `phone_numbers`, `emails` and `organization` is given. |
| 400 | `bad_request` | The chat's contact is not a phone number. |
| 403 | `forbidden` | The request uses a line-scoped key, and the chat's line is not in its list. |
| 404 | `not_found` | The chat is unknown, or its line is not yours. |
| 409 | `idempotency_conflict` | The `Idempotency-Key` was already used on the chat's line, by an earlier call of this operation that created the card's message or by a `POST /v1/messages`. |
| 502 | `avatar_fetch_failed` | iSnap fetches `avatar_url` once without following a redirect. The fetch failed: the host does not resolve to a public address, the response is not a `2xx` with a `Content-Type` of `image/png` or `image/jpeg`, the image is over 2,097,152 bytes (2 MiB), or the download did not finish within 5 seconds. Nothing is sent. |

The other errors of [`POST /v1/messages`](/api-reference/messages/send-message) also apply: the line errors, the `429` codes of the sending limits, and the `503` codes of a shared line. The errors that every operation shares are in [Errors](/errors-and-rate-limits#errors).
