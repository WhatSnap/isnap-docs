The iSnap API sends and receives iMessage, RCS and SMS from real devices. It is for developers who add messaging to their own product, and for the coding agents and AI agents that work with them. You obtain lines, send and receive messages on them, and learn what happened to each message by webhook.

The API serves lines, messages, chats, attachments, recipient lookups, trials, BYOD pairing, pre-orders, hosted macOS sessions and webhook subscriptions. Two things are done outside the API:

- API keys are created and revoked in the [iSnap dashboard](https://platform.isnap.ai).
- A direct account pays in the iSnap dashboard, by card: it buys lines, BYOD slots and hosted macOS sessions there, and pays the first month of a [pre-order](/guides/pre-orders#confirm-and-payment). See [Accounts](/concepts#accounts).

For what only iSnap can do, such as granting wholesale partner status or lifting the suspension of a line, write to [support@isnap.ai](mailto:support@isnap.ai).

## The path to a first call

1. Sign up at [platform.isnap.ai/signup](https://platform.isnap.ai/signup), then create an API key in the [iSnap dashboard](https://platform.isnap.ai). The full key is shown once.
2. Call `GET /v1/version`, which needs no key, to check that you reach `https://api.isnap.ai`.
3. Call `GET /v1/lines/my` with your key to list your lines.
4. Send a message from an active line to a phone number of your own, then read its status.

A new account has no line, and `GET /v1/lines/my` returns an empty `lines`: see [Getting a line](/guides/getting-a-line).

The [Quickstart](/quickstart) runs these four steps, in curl, TypeScript and Python.

Know this before the first send. An `isnap_test_` account key is not a separate test environment: it acts on the same account, lines and billing as an `isnap_live_` key. Every send is a real message to a real recipient. See [Test keys](/authentication#test-keys).
