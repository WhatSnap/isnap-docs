title: "BYOD pairing"

BYOD ("bring your own device") lets you connect your existing hardware
to iSnap and start sending under the API. The flow is four steps: mint
an activation code, install the bridge, enter the code, done.

## When BYOD is the right pick

| If you… | Pick… |
|---|---|
| have your own Mac + iPhone | `macos_byod` |
| have an Android phone on a real SIM | `android_byod` |
| don't have hardware or don't want to manage it | rental (not this guide) |

[Concepts → BYOD vs Rental](/concepts/byod-vs-rental) covers the
trade-offs in depth.

## 1. Mint an activation code

<Tabs>
  <Tab title="TypeScript SDK">
    ```ts
    const pair = await isnap.byod.pair({
      device_type: 'macos_byod',           // or 'android_byod'
      device_name: 'Reception Mac Mini'    // shows up in your dashboard
    })

    console.log(pair.activation_code)        // 'act_4Lp8Rn9Fh2'
    console.log(pair.expires_at)             // ISO timestamp, +5 min from now
    console.log(pair.bridge_download_url)    // .dmg (macOS) / .apk (Android)
    console.log(pair.bridge_version)         // '2.0.1'
    console.log(pair.setup_instructions_url) // deep link to setup docs
    ```
  </Tab>
  <Tab title="cURL">
    ```bash
    curl -X POST https://api.isnap.ai/v1/byod/pair \
      -H "Authorization: Bearer $ISNAP_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "device_type": "macos_byod",
        "device_name": "Reception Mac Mini"
      }'
    ```
  </Tab>
</Tabs>

The `activation_code` (`act_…`) is **single-use** and **expires in
5 minutes**. The download URL is stable — same URL for every pairing,
no expiry — so cache it if you want.

### Errors

| HTTP | `error.code` | Cause |
|---|---|---|
| 402 | `no_byod_slot_available` | Your BYOD subscription has no free slot. Release an existing pairing or upgrade your plan. |
| 422 | `validation_error` | Bad `device_type` or empty `device_name`. |

## 2. Install the bridge

Open `setup_instructions_url` for the platform-specific walkthrough.
The steps:

1. Download the bridge from `bridge_download_url`.
2. Open the installer.
3. Enter the `activation_code` when prompted.
4. Grant macOS Full Disk Access (Mac) or default-SMS-app permission
   (Android).

The bridge then opens a long-lived connection to iSnap, presents a
device fingerprint, and the activation code is consumed.

<Note>
On macOS, the iMessage bridge requires both a paired iPhone (via
Continuity) and your Apple ID. iSnap doesn't store Apple ID
credentials — the bridge handles auth locally and only sends iSnap
session tokens.
</Note>

## 3. Server activation

Once the bridge connects with a valid activation code, iSnap mints
the new line on your account:

- A `line.connected` webhook fires with the new `line_id` and `byod: true`.
- The line shows up in `GET /v1/lines/my` with `status: "active"`
  once the bridge confirms it can send.

After that, the line is just a normal iSnap line — `POST /v1/messages`
with the new `line_id` and you're sending.

## 4. Health monitoring

BYOD lines expose the **full health surface** because you own the
hardware and can act on issues:

- `line.connected` / `line.disconnected` — the bridge regained /
  lost its long-lived connection.
- `line.offline` — the bridge has been unreachable past the
  threshold.
- `line.degraded` — the bridge is online but missing heartbeats.
- `GET /v1/lines/{id}/health` returns the current state +
  last-seen-at + recent error history.

Rental lines suppress these transient events to avoid alert noise. See
[Concepts → BYOD vs Rental](/concepts/byod-vs-rental#what-events-you-receive)
for the full matrix.

## Re-pairing a device

Each BYOD slot holds one device. If you swap (replaced an iPhone,
lost a Mac), call `POST /v1/byod/pair` again with the same
`device_name` — the new activation code supersedes any previous
pairing on that slot.

To free a slot entirely (cancellation), release the line via
`POST /v1/lines/{id}/release`. The bridge has nowhere to send to and
the slot frees up.
