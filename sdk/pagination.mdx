---
title: "Pagination"
description: "AsyncIterable list methods, filtering, abort signals."
---

The SDK exposes paginated list methods as `AsyncIterable`s. You can
`for await` over the entire result set without thinking about cursors.

## Basic pattern

```ts
for await (const message of isnap.messages.list({ line_id: 'line_aBc...' })) {
  console.log(message.id, message.body)
}
```

The iterator pulls subsequent pages automatically and stops when the
server reports there are no more.

## Filtering

Pass filters as the first argument; they apply to every page:

```ts
for await (const m of isnap.messages.list({
  line_id: 'line_aBc...',
  status: 'delivered',
  since: '2026-05-01T00:00:00Z'
})) {
  // ...
}
```

Filters bind to the iteration. Don't change them mid-loop — start a
fresh iterator if you need a different filter set.

## Stop early

Standard `break` works:

```ts
let count = 0
for await (const m of isnap.messages.list({ line_id })) {
  if (++count >= 100) break
  process(m)
}
```

Once you break out, the iterator stops fetching subsequent pages.

## Abort signals

For long iterations that need to be cancellable, pass an `AbortSignal`:

```ts
const controller = new AbortController()
setTimeout(() => controller.abort(), 30_000)   // 30s ceiling

try {
  for await (const m of isnap.messages.list({ line_id }, { signal: controller.signal })) {
    process(m)
  }
} catch (err) {
  if (err instanceof APIConnectionError) {
    console.warn('Iteration aborted')
  }
}
```

The SDK throws `APIConnectionError` with the abort reason as `cause`.
Abort happens between page fetches — the current page is fully
consumed before the abort kicks in.

## Page size

You don't pick a page size — the SDK and the server negotiate one
that's appropriate for the resource. The iterator hides it.
