---
title: "Look up a handle"
description: "Check if a phone number is reachable on iMessage before cold outbound."
---

`isnap.lookup.check()` is the synchronous pre-send probe — call it on any
handle you've never messaged to find out whether iMessage is an option.

## Basic call

```ts
import { ISnapClient } from '@isnap/sdk'

const isnap = new ISnapClient({ apiKey: process.env.ISNAP_API_KEY! })

const probe = await isnap.lookup.check({ handle: '+15551234567' })
console.log(probe.handle)      // echoes the canonicalised input
console.log(probe.imessage)    // true | false | null
```

## The shape

The response carries two fields:

| Field | Meaning |
|---|---|
| `handle` | The canonicalised E.164 phone or normalised email you queried. |
| `imessage` | `true` reachable, `false` confirmed not on iMessage, `null` unknown (no probe data — treat as SMS-safe). |

That's it. No `facetime`, no `line_type`, no `carrier`, no `cached` /
`pending` / `retry_after` — the schema was trimmed pre-launch to only
the signal we reliably populate. See
[`POST /v1/lookup`](/api-reference/lookup/post-lookup) for the
underlying contract.

## Example response

```json
{
  "handle": "+15551234567",
  "imessage": true
}
```

When the probe can't conclude (recipient never reached on iMessage,
provider lookup timed out, etc.) you get `imessage: null` and treat
it as "play it safe":

```json
{
  "handle": "+15551234567",
  "imessage": null
}
```

## Use it to inform routing

`channel` on `POST /v1/messages` is locked to `auto` in v1, so lookup
doesn't change what you pass — it changes which **line** you send from.
Send from an iMessage-first line (`rental_iphone` / `byod_imessage`)
when iMessage is reachable; otherwise use an Android line so the
fallback chain starts on SMS / RCS.

```ts
async function pickLineFor(to: string): Promise<string> {
  const probe = await isnap.lookup.check({ handle: to })

  if (probe.imessage === true) {
    return MY_IMESSAGE_LINE_ID
  }
  // false or null — assume SMS-safe routing
  return MY_ANDROID_LINE_ID
}
```

## Pre-validating a list

For batch outreach, drop the unreachable handles before you queue sends:

```ts
async function partitionByImessage(handles: string[]) {
  const imessage: string[] = []
  const smsOnly: string[] = []
  const unknown: string[] = []

  // Lookup is per-call; the SDK doesn't bulk-batch (server-side limit).
  // Run with a small concurrency budget to avoid hammering rate limits.
  const concurrency = 5
  for (let i = 0; i < handles.length; i += concurrency) {
    const batch = handles.slice(i, i + concurrency)
    const results = await Promise.all(
      batch.map((h) => isnap.lookup.check({ handle: h }))
    )
    for (let j = 0; j < batch.length; j++) {
      const probe = results[j]
      const handle = batch[j]
      if (probe.imessage === true) imessage.push(handle)
      else if (probe.imessage === false) smsOnly.push(handle)
      else unknown.push(handle)
    }
  }

  return { imessage, smsOnly, unknown }
}
```

## Errors

| HTTP | `error.code` | What |
|---|---|---|
| 422 | `validation_error` | `handle` malformed (must be E.164 or email). |
| 429 | `lookup_rate_limit_exceeded` | You're calling lookup too aggressively. Back off. |

`lookup_rate_limit_exceeded` is a `QuotaExceededError` — see
[SDK → Errors](/sdk/errors). Honour `retryAfter`.
