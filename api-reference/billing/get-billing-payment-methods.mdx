---
title: "List payment methods"
description: "Cards on file — brand, last 4, expiry, which one is the default."
openapi: "GET /v1/billing/payment-methods"
---

Returns the Stripe payment methods attached to your account. The
default one is what Stripe charges on each calendar-month invoice.

## Response shape

```json
{
  "success": true,
  "data": [
    {
      "id": "pm_...",
      "brand": "visa",
      "last4": "4242",
      "exp_month": 12,
      "exp_year": 2028,
      "is_default": true
    }
  ],
  "trace_id": "tr_...",
  "request_id": "req_..."
}
```

| Field | Notes |
|---|---|
| `id` | Stripe payment method ID. Pass to `DELETE` / `set-default` endpoints. |
| `brand` | `visa`, `mastercard`, `amex`, `discover`, etc. Lowercase. |
| `last4` | Last 4 digits of the card. |
| `exp_month` / `exp_year` | Expiry. Render as `MM / YY` in your UI. |
| `is_default` | Exactly one card in the list has this set to `true` (when any cards exist). |

## How to add a card

Two paths:

| You want… | Use |
|---|---|
| A Stripe-hosted checkout UI (with the line subscription bundled) | [`POST /v1/billing/checkout`](/api-reference/billing/post-billing-checkout) |
| Just to capture a payment method, no subscription | [`POST /v1/billing/payment-methods`](/api-reference/billing/post-billing-payment-methods) — returns a Stripe SetupIntent client secret your front-end mounts via Stripe Elements |

## Errors

Universal codes (`401 invalid_api_key`, `500`, `503`) and the envelope
shape are documented in
[Conventions → Errors](/api-reference/introduction#errors). This
endpoint has no endpoint-specific error codes.
