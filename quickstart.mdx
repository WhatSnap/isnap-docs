This walkthrough takes you from zero to a delivered message. Pick the
SDK flow if you're integrating from a Node, Bun, or Deno service; pick
the cURL flow if you're exploring or wiring from a non-TypeScript
environment.

## 1. Create an account

Sign up at [platform.isnap.ai/signup](https://platform.isnap.ai/signup),
verify your email, and complete the onboarding form. You'll land on the
dashboard with a default test environment ready to use.

## 2. Mint an API key

In the dashboard: **Developers → API keys → Create key**.

- **Environment:** pick `test` for sandboxing, `live` for production.
  Test keys produce real-looking responses but never hit a real device.
- **Scope:** leave unscoped for the quickstart.

Copy the key. It looks like `isnap_test_aBcD…` or `isnap_live_xYz…`.
**This is the only time iSnap shows you the full string** — store it in
your secret manager now.

<Warning>
API keys grant the ability to send messages billed to your account.
Treat them like passwords: never commit them to git, never log them in
plaintext, never put them in a frontend bundle.
</Warning>

## 3. Send a message

<Tabs>
  <Tab title="TypeScript SDK">
    Install:

    ```bash
    bun add @isnap/sdk
    # or: npm install @isnap/sdk
    ```

    Send:

    ```ts
    import { ISnapClient } from '@isnap/sdk'

    const isnap = new ISnapClient({
      apiKey: process.env.ISNAP_API_KEY!
    })

    // Pick one of your active lines (`isnap.lines.listMine()`).
    // `channel: 'auto'` lets the line pick iMessage → RCS → SMS based
    // on what reaches the recipient.
    const message = await isnap.messages.send({
      line_id: 'line_aBcDeF',
      to: '+15551234567',
      channel: 'auto',
      body: 'Hello from iSnap.'
    })

    console.log(message.id)         // 'msg_01HX…'
    console.log(message.status)     // 'queued'
    ```
  </Tab>
  <Tab title="cURL">
    ```bash
    curl -X POST https://api.isnap.ai/v1/messages \
      -H "Authorization: Bearer $ISNAP_API_KEY" \
      -H "Content-Type: application/json" \
      -H "Idempotency-Key: $(uuidgen)" \
      -d '{
        "line_id": "line_aBcDeF",
        "to": "+15551234567",
        "channel": "auto",
        "body": "Hello from iSnap."
      }'
    ```

    Response:

    ```json
    {
      "success": true,
      "data": {
        "id": "msg_01HX...",
        "line_id": "line_aBcDeF",
        "direction": "outbound",
        "to": "+15551234567",
        "from": "+15559998888",
        "channel": "auto",
        "service": null,
        "body": "Hello from iSnap.",
        "status": "queued",
        "created_at": "2026-05-05T14:32:00Z"
      },
      "trace_id": "tr_...",
      "request_id": "req_..."
    }
    ```

    `service` is `null` until iSnap dispatches: it commits to
    `iMessage`, `SMS`, or `RCS` at send time based on recipient
    reachability and the line's fallback chain.
  </Tab>
</Tabs>

The response wraps the payload in a standard envelope (`success`,
`data`, `trace_id`, `request_id`). This shape is identical for every
successful response — see [API Reference → Conventions](/api-reference/introduction).

## 4. Watch it deliver

The `status` field starts as `queued` and progresses through
`sent → delivered` (or `failed`) over the next few seconds. Two ways
to track it:

<Tabs>
  <Tab title="Webhook (recommended)">
    Register a webhook subscription in **Developers → Webhooks → New
    subscription**. Point it at an endpoint you control, subscribe to
    `message.sent` and `message.delivered`.

    Every event POSTs to your URL with an HMAC-SHA256 signature in the
    `X-iSnap-Signature` header. **Verify it** before trusting the
    payload — see [Set up webhooks](/guides/webhooks).
  </Tab>
  <Tab title="Polling (for the quickstart only)">
    ```ts
    let m = await isnap.messages.get(message.id)
    while (m.status === 'queued' || m.status === 'sent') {
      await new Promise((r) => setTimeout(r, 1000))
      m = await isnap.messages.get(message.id)
    }
    console.log(m.status)
    ```

    <Warning>
    Polling is fine for exploration. **Never poll in production** — it
    burns rate limit and adds delivery latency. Use webhooks.
    </Warning>
  </Tab>
</Tabs>
