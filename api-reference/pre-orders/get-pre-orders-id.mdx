---
title: "Get a pre-order"
description: "Single pre-order — current status, estimated fulfillment, and the line ID once it lands."
openapi: "GET /v1/pre-orders/{id}"
---

Returns a specific pre-order. Use it to poll a single record's status
without paging through the full list.

## Path parameters

| Param | Value |
|---|---|
| `id` | The pre-order's UUID, returned from [`POST /v1/pre-orders`](/api-reference/pre-orders/post-pre-orders). |

## Response

A `PreOrder` record. See
[`POST /v1/pre-orders`](/api-reference/pre-orders/post-pre-orders)
for the field guide.

The fields you'll care about while polling:

| Field | What to watch for |
|---|---|
| `status` | Move through `pending → provisioning → fulfilled`. |
| `fulfilled_line_id` | Populated once the line is live. Use it to call line endpoints. |
| `device_status` | Internal provisioning state. Surfaces "where in the operator workflow" — useful for ops dashboards. |
| `estimated_fulfillment` | Updates as iSnap revises the ETA. |

Once `status: "fulfilled"`, treat the pre-order as terminal — switch
your code path to using `fulfilled_line_id` against the Lines API.

For "tell me when this pre-order is ready" subscribe to
[`pre_order.fulfilled`](/api-reference/webhooks/get-webhooks-events)
instead of polling this endpoint.

## Errors

Universal codes (`401 invalid_api_key`, `500`, `503`) and the envelope
shape are documented in
[Conventions → Errors](/api-reference/introduction#errors).
Endpoint-specific codes:

| HTTP | `error.code` | Cause |
|---|---|---|
| 404 | `pre_order_not_found` | `id` isn't on your account. |
| 422 | `validation_error` | `id` not a valid UUID. |
