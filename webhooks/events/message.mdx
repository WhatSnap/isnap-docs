title: "Message events"
description: "Gives the data of message.queued, message.scheduled, message.sent, message.delivered, message.read, message.failed, message.received, message.cancelled and message.fallback_triggered, with an example of each and the personal data they carry."
---

The `message.*` events follow a message from the moment iSnap accepts or receives it. For each of the
nine event types, this page says when it is sent and when it is not, lists the fields of `data`, and
shows a full event. You need it to track a send to its final status and to receive inbound messages.

A send through the API produces `message.queued`, or `message.scheduled` when the message is held and
then `message.queued` when it is released. `message.sent` or `message.failed` follows, then
`message.delivered` and `message.read` if the line's device reports them, and
`message.fallback_triggered` when the device sent, or tried to send, the message over SMS or RCS.
Delivery order is not guaranteed. Order events by the timestamps inside `data`, not by arrival:
`message.delivered` can reach you before `message.sent`. See
[Sending messages](/guides/sending-messages) for the statuses of a message.

## Common fields

Every `message.*` event carries these fields in `data`. The sections below list the fields each
event type adds.

| Field | Type | Nullable | Meaning |
| --- | --- | --- | --- |
| `message` | object | No | The full message object, as [`GET /v1/messages/{id}`](/api-reference/messages/get-message) returns it, in its state after the change. Its `queue_info` is always `null` in an event. |
| `metadata` | object | Yes | The `metadata` of the message. `null` when the message has none, on every inbound message, and when the message belongs to an account that owned the line before you: `message.metadata` still carries it then. |
| `line_metadata` | object | Yes | The `metadata` of the message's line, when that line belongs to your account. See [`metadata` and `line_metadata`](/webhooks/event-catalog#metadata-and-line_metadata). |

The message object has no `chat_id`. Three events carry the chat id beside `message`:
`message.received`, `message.sent` with `origin: "device"`, and the `message.read` that follows your
own mark-read call.

The message events of a trial are tied to the trial's pool line. A subscription with a line
filter receives them only if it lists that line id.

On a line that another account owned before you, you receive the device reports about the messages
of that account: see [Lines that change owner](/webhooks/overview#lines-that-change-owner).

**Personal data.** `data.message` carries the message text, the handles of the contact and of the
line (phone numbers or email addresses), attachment file names and the handles of the senders of
reactions. `message.received` can add `contact_name`. Subscribe to message events only when you need
them. Do not copy this data into logs, tickets or other tools. Refer to a contact by an id of your
own.

## `message.queued`

Sent when:

- a message is accepted for immediate sending, by
  [`POST /v1/messages`](/api-reference/messages/send-message), by
  [`POST /v1/chats/{chat_id}/share-contact-card`](/api-reference/chats/share-contact-card), or by a
  send with a trial key;
- a held message is released for sending. In that case the event is skipped if the message is no
  longer `queued` at that moment.

`data` holds the common fields only.

```json
{
  "api_version": "v1",
```

## `message.scheduled`

Sent when a message is accepted but held, and again each time its planned send time moves by more
than 15 minutes. A smaller move sends nothing. `message.queued` follows when the message is
released. See [Held messages](/guides/sending-limits#held-messages).

| Field | Type | Nullable | Meaning |
| --- | --- | --- | --- |
| `message` | object | No | The message, with `status: scheduled`. |
| `schedule_reason` | string | No | Why the message is held. The same value as `message.schedule_reason`. |
| `scheduled_for` | string | No | The planned send time, as a timestamp. The same value as `message.scheduled_for`. |

## `message.sent`

Sent in two cases, told apart by `data.origin`.

Common fields:

| Field | Type | Nullable | Meaning |
| --- | --- | --- | --- |
| `message` | object | No | The message. |
| `sent_at` | string | No | The time of the send. For `origin: "api"` it is the time iSnap recorded the confirmation. For `origin: "device"` it is the time the device gives. |
| `origin` | string | No | `api` or `device`. |

no `message.delivered` and with `delivered_at` still `null`.

## `message.read`

Sent in two cases. Every case carries `message` and `read_at`: rely on these two fields, and treat
the others as present only in their case.

| Field | Type | Nullable | Meaning |
| --- | --- | --- | --- |
| `message` | object | No | The message, with `read_at` set. |
| `read_at` | string | No | The time the message was read, or the time of your mark-read call. |

The first case concerns a message you sent, whose `message.status` is `read`. The second concerns an
inbound message: `message.direction` is `inbound`, and `message.status` stays `delivered`.

### The recipient read your message

The line's device reports that the recipient read an outbound message. `data` holds the two common
fields and can add `message_id`, `line_id` and `status` (always `read`); on an iMessage line it
always adds them.

| --- | --- | --- | --- |
| `message_id` | string | Absent on some lines; always present on an iMessage line | The id of the message. |
| `line_id` | string | Absent on some lines; always present on an iMessage line | The id of the message's line. |
| `status` | string | Absent on some lines; always present on an iMessage line | Always `read`. |

## `message.failed`

Sent in three cases. Every case carries `message` and `failed_at`. For the cause, read
`message.error_code` and `message.error_message`: they have one meaning in every case, while the
fields beside `message` differ.

| Field | Type | Nullable | Meaning |
| --- | --- | --- | --- |
| `message` | object | No | The message, with `status: failed`. |
| `failed_at` | string | No | The time of the failure. |

iSnap never resends a failed message: send a new message to retry. See
[Sending messages](/guides/sending-messages).

## `message.received`

Sent when an inbound message is stored. An inbound message has `status: delivered`.

| Field | Type | Nullable | Meaning |
| --- | --- | --- | --- |
| `message` | object | No | The inbound message. |
| `chat_id` | string | No | The chat of the message. |
| `received_at` | string | No | The time the device gives for the reception. |
| `contact_name` | string | Absent when the device reports none | The display name of the sender, as the line's device knows it. |

The event is not sent:

- on a shared line, for a message from a contact the line has no active binding with;
- on a line that runs trials, for the text that carries a pairing code, and for a message from a
  sender who is not the paired prospect of a trial;
- for a second copy of a message the device reports twice;
- for history that a device reports from before iSnap was watching the line.

## `message.fallback_triggered`

Sent when the line's device reports that a message went out, or was attempted, over SMS or RCS
instead of iMessage, whether that attempt succeeded or failed. It does not prove that an iMessage
attempt was made first: the device also reports it for a message it sent directly as SMS or RCS
because it already knew the recipient is not on iMessage. The same report also produces
`message.sent` or `message.failed`.

| Field | Type | Nullable | Meaning |
| --- | --- | --- | --- |
| `message` | object | No | The message. |
| `fallback_service` | string | No | `iMessage`, `SMS` or `RCS`. `SMS` when the device names no service. |
| `triggered_at` | string | No | The time iSnap recorded the fallback. |
